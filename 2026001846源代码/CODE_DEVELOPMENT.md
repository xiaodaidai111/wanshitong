# 代码开发规范

## 核心原则

- 不要使用兜底逻辑掩盖真实错误。
- 接口失败、模型不可用、数据为空、配置缺失时，应明确暴露错误状态和原因。
- 不要用默认假数据、固定回复、静态占位结果冒充真实功能可用。
- 不要把异常吞掉后返回“看起来正常”的结果。
- 前端应展示清晰错误提示，后端应返回明确错误码、错误信息和可定位的失败原因。

## AI 功能要求

- AI 对话、图片识别、语音识别、语音合成、RAG 检索等功能必须调用真实接口。
- 如果模型接口不可用，应提示“模型服务不可用”或具体失败原因。
- 如果知识库没有命中，应返回“未检索到相关知识”，不要自动生成伪答案。
- 如果 API Key、Base URL、依赖或公网访问条件缺失，应直接报错并说明缺失项。

## 开发与调试要求

- 修复问题时优先定位真实原因，而不是增加兜底分支。
- 测试通过必须基于真实接口、真实数据或明确的模拟测试环境。
- 仅在用户明确要求“演示模式”“离线模式”“模拟数据”时，才允许加入 mock 或 demo 数据。
- 新增异常处理时，必须保留错误信息，方便继续排查。
